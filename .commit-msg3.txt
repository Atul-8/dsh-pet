fix(helper): 桌面端右键菜单崩溃——shared-core 陈旧产物重建 + bundle 链根治

症状（独立应用打包验证时实锤）：渲染端 Uncaught TypeError:
S.buildMoreBranch is not a function（sprite.js:1654）。

根因链（比表面深两层）：
1. 桌面 helper 的 shared-core.js 是 src/shared/index.ts 的 rolldown
   **构建产物**（gitignore 不入库，现场生成）——不是手维护的副本；
2. 浏览器侧加第三方菜单三函数（readMenuItems / buildMoreBranch /
   MORE_MENU_LABEL）时只跑了 pnpm run bundle（重建 lib/），
   desktop-core 的重建在 npm run build / prepare 发布链里，日常
   开发链不经过——产物停在加功能前的版本；
3. 于是 events.js 首拍 applyMenuLeaf 就抛错（S.readMenuItems 也
   undefined，被轮询 catch 吞掉），右键菜单 handler 在 buildMoreBranch
   处 TypeError 中断——**桌面端整个右键菜单挂**，不止缺「更多」一枝。

修（两层，治标+治本）：
- 立即：node scripts/build-desktop-core.mjs 重建产物（源里 index.ts
  本就 export * from './menu'，三函数一应俱全——重建即恢复）；
- 根治：package.json 的 bundle 脚本串联 build:desktop-core
  （tsdown && node scripts/build-desktop-core.mjs）——浏览器/桌面
  两个产物从此同一命令同步产出，"改 shared 忘记重建桌面侧"这类
  漂移在构建链上不可能再发生。

顺带对齐（重建产物自然带回，非手改）：
- mountContextMenu 叶子分支的 hint 渲染（dsh-pet-menu-hint）
- 菜单 CSS 的 .dsh-pet-menu-hint 规则 + max-width 240→300px
  （与浏览器侧 MENU_CSS 同源同步）

坑位存档：shared-core.js 是 IIFE 全局 PetShared（经典 script，非
CJS）——Node 侧 require 拿到空 exports 是假阴性，验证要用
new Function(src + '; return PetShared;')() 的浏览器口径。

验证：pnpm run bundle 串联重建（两个产物零陈旧）+ IIFE 口径
三函数/分组/坏数据静默丢弃全过 + 门禁 tsc/lint/format/1064 测试
fail 0 + lib 零 oxc 引用。
